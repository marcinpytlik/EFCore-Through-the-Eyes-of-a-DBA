# Course Map — 3-Day Student Track

# EF Core Through the Eyes of a DBA — What Really Reaches SQL Server?

This is the recommended path through the student repository.

The course connects two views of the same system:

- application code: C#, LINQ, EF Core, endpoints,
- database evidence: SQL, execution plans, logical reads, locks, waits and Query Store.

The working rule for all three days is:

> **Collect evidence first. Draw conclusions second.**

## Mental model

```text
Application decision
        ↓
Generated SQL
        ↓
Execution plan / locks / waits
        ↓
Database workload
        ↓
Observed API behaviour
        ↓
Evidence
        ↓
Root cause
        ↓
Fix
        ↓
Validation
```

## What you should be able to do at the end

You should be able to:

- find SQL generated by EF Core,
- connect LINQ shape to generated SQL,
- identify the moment a query is materialized,
- compare full-entity loading with projection,
- inspect Actual Execution Plans and logical reads,
- reason about Scan, Seek and Key Lookup in context,
- recognize non-SARGable predicates,
- diagnose blocking and identify the blocker,
- explain the difference between blocking and deadlock,
- use Query Store to identify workload patterns,
- distinguish one large query from N+1,
- classify a problem as Application / Database / Both,
- propose a fix and define how to validate it.
